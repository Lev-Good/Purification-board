# DECISIONS.md — החלטות משמעותיות

## 2026-09-17 — השלמת סבב שדרוג קודם והכשרת הפרויקט להפצה

### ההחלטה
לא בוצע שדרוג ארכיטקטוני נוסף. הוחלט לבצע סריקה מלאה של הפרויקט (שעבר בעבר שדרוג עיצובי ומעבר למבנה מודולרי — commit `3d7cf9c` ואילך), לאמת שכל זרימות העבודה פועלות בפועל (לא רק בקריאת קוד), ולתקן רק את הבאגים שנמצאו בפועל — ללא רה-פקטורינג נוסף שלא התבקש.

### הסיבה
בקשת המשתמש הייתה "לסרוק את כל הפרויקט... ולזהות מה עוד לא הושלם ולתקן ולהשלים שיהיה מוכן להפצה מלאה". בדיקה ידנית מקיפה (דפדפן חי + אריזת Electron בפועל) העלתה שהליבה התפקודית שלמה ותקינה; הבעיות שנמצאו היו נקודתיות.

### באגים שנמצאו ותוקנו
1. **SVG שבור באייקון "ריכוז וסתות"**: תג `<path>` נפתח ולא נסגר (`</path>` חסר) בשלושה מקומות — `index.html` (פעמיים) ו-`js/icons.js`. תוקן.
2. **משתני CSS לא מוגדרים**: `--shadow-lg` ו-`--surface-hover` נעשה בהם שימוש (בתצוגה השנתית, ב-hover ובכותרת החודש) מבלי שהוגדרו ב-`:root`/`[data-theme="dark"]`, מה שגרם לצל/רקע חסרים באפקט ה-hover. נוספו הגדרות לשני המצבים (בהיר/כהה).
3. **`icon.png` חסר מרשימת `files` באריזת electron-builder**: `main.js` טוען את האייקון ב-runtime מתוך תיקיית האפליקציה הארוזה, אך הקובץ לא הוגדר להיכלל ב-`app.asar`. תוקן ואומת בפועל (`npm run pack` + פתיחת ה-exe שהתקבל, בדיקת `asar list`).
4. **קוד מת**: שני stub ריקים (`window.moveToNext`, `window.handleBackspace`) ב-`js/app.js` שלא נקראו משום מקום (שרידים מגרסה קודמת לפני שה-PIN input logic עבר ל-`security.js`). הוסרו.

### חלופות שנשקלו
לא נשקלו חלופות ארכיטקטוניות — מדובר בתיקוני תקינות ממוקדים, לא בהחלטת עיצוב.

### השלכות
- אין שינוי ב-API הפנימי, ב-schema של ה-DB, או בזרימת המשתמש.
- הבילד של Electron (`npm run pack`/`npm run dist`) כעת מייצר קובץ הפעלה עם אייקון תקין.
- הוגדרה `allowScripts` חדשה ב-`package.json` (על ידי `npm approve-scripts electron`) לצורך אישור סקריפט ה-postinstall של Electron בסביבת בנייה עם allow-scripts — נדרש כדי ש-`npm install` יוריד בפועל את בינארי Electron.

### נושאים שזוהו אך *לא* שונו (במכוון)
- שחזור PIN דרך Google Apps Script שולח את ה-PIN בטקסט גלוי לשירות חיצוני. זו התנהגות קיימת ומתועדת (לא נוספה/שונתה כעת) — ראו [ARCHITECTURE.md](ARCHITECTURE.md#אבטחה-ונעילה). אם ברצון המשתמש לשנות זאת, נדרשת החלטת מוצר נפרדת (לדוגמה: שליחת OTP חד-פעמי במקום ה-PIN עצמו).
- קובצי גיבוי (`taharah_backup.json`) אינם מוצפנים.
- אין תמיכה ב-macOS/Linux באריזת ה-Electron (Windows בלבד כרגע) — לא התבקש שינוי.

## 2026-09-17 (המשך) — מימוש "אפיון תוספות עתידיות מתוכננות" במלואו

### ההחלטה
לממש את כל סעיפי הרשימה `אפיון תוספות עתידיות מתוכננות.txt` (קובץ מקומי אצל המשתמש, לא במעקב git) בבת אחת, לפי בקשת המשתמש "פשוט בצע הכל. ואז תכין להפצה מלאה כל מה שצריך". פירוט הסעיפים והמימוש המלא ב-[TASKS.md](TASKS.md) וב-[SPEC.md](SPEC.md).

### הסיבה
המשתמש ביקש מפורשות לממש את כל הרשימה ולא רק חלק ממנה, ולאחר מכן להכין את הפרויקט להפצה מלאה.

### החלטות מימוש מרכזיות (ולמה)

1. **מיקום סימוני "נקיים"/"טבילה" בלוח** — המשתמש עצמו כתב מסקנה מפורשת בקובץ ("יש לשבץ את היום הראשון של הנקיים בראש הקוביה של ט"ז"). יישמתי בדיוק את המסקנה הזו כפי שנכתבה (לא פרשנות הלכתית עצמאית שלי): יום 1 של הנקיים → חלק עליון (לילה) של אותו יום; צפי/רישום טבילה → חלק עליון של היום שאחרי. אומת מול הדוגמה המספרית המדויקת שהמשתמש נתן (הפסק בט"ו → נקיים יום 1 ב-ט"ז, טבילה ב-כ"ג) בבדיקה אוטומטית בדפדפן. **חשוב**: זהו יישום טכני של מסקנה שכתב המשתמש, לא פסיקה הלכתית של הכלי — לגבי שאלות הלכתיות בפועל יש להתייעץ עם פוסק.
2. **יום הלכתי לפי שקיעה** — נעשה שימוש במחלקות `Location`/`Zmanim` שכבר קיימות בתוך `hebcal.js` המוטמע (כולל רשימת ~65 ערים מוכנה), ולא נוספה תלות/API חיצוני חדש. ללא בחירת עיר על ידי המשתמש, ההתנהגות נשארת בדיוק כמו קודם (חצות לועזי) — כדי לא לשנות בהפתעה משתמשים קיימים שלא יבחרו עיר.
3. **תאריך לידה משוער** — מוצג רק לאחר 35+ יום ללא הפסק טהרה (לא מיד בכל מחזור), ותמיד עם ניסוח "אם קיים הריון" ואזהרה שזו הערכה גסה בלבד ואינה תחליף לייעוץ רפואי — כדי לא ליצור רושם של אבחון/ייעוץ רפואי מהכלי.
4. **התראות מחשב** — נבחר Web Notification API (עובד זהה בדפדפן וב-Electron) על פני מודול native נפרד, כדי לשמור על בסיס קוד משותף. גוף ההתראה נשאב מהטקסט שכבר מוצג בדשבורד (לא לוגיקה כפולה) כדי למנוע סטייה (drift) בין השניים.
5. **מגש מערכת + הפעלה אוטומטית** — הוגדרו כהגדרה *אחת* משותפת (לא שתי הגדרות נפרדות), כי המטרה המוצהרת של "הפעלה אוטומטית" הייתה "כדי שההתראות יגיעו גם כשהיא סגורה" — כלומר שתי ההתנהגויות (auto-launch + מזעור למגש במקום סגירה) משרתות אותה מטרה ומופעלות/מכובות יחד. כשההגדרה כבויה, ההתנהגות זהה לחלוטין למה שהיה קודם (סגירה = יציאה מלאה) — לא נכפתה התנהגות רקע על משתמשים שלא ביקשו זאת.
6. **בדיקת עדכונים** — `autoDownload = false`: הבדיקה/הורדה/התקנה כולן יזומות על ידי המשתמש דרך כפתור בהגדרות, לא מתבצעות אוטומטית ברקע. קונפיגורציית `publish` הוגדרה מול המאגר האמיתי (`Lev-Good/Purification-board`, יש remote git תואם), אך **לא בוצע כל פרסום (publish) בפועל** — זו פעולה בעלת נראות ציבורית שדורשת אישור מפורש נפרד, ולא התבקשה.
7. **המרת `icon.png`** — הקובץ המקורי היה בפועל JPEG עם סיומת `.png` שגויה (זוהה עם ה-בדיקה של magic bytes: `FFD8FF...` = JPEG, לא `89504E47` = PNG). הומר לקובץ PNG תקין (1024×1024) באמצעות `nativeImage` המובנה של Electron, ללא אובדן תוכן חזותי (ל-JPEG ממילא אין ערוץ שקיפות שהיה אפשר לאבד).
8. **עיצוב מינימליסטי** — נבחר מעבר ממוקד (צבעי מרקר שטוחים במקום גרדיאנט, הסרת אנימציית פעימה אינסופית על "היום", הקלה בצללים) ולא רה-דיזיין מבני מלא, כדי לא לערער ממשק שכבר נבדק ועובד היטב. תוך כדי כך נמצא ותוקן באג קיים: מחלקת `.alert-pulse` נקראה מ-`js/ui.js` אך לא הייתה מוגדרת כלל ב-CSS (אנימציה חסרה על אייקון האזהרה בדשבורד).

### חלופות שנשקלו
- עבור ההתראות: נשקל מודול Notification native של Electron (`new Notification` בתהליך ה-Main) — נדחה לטובת Web Notification API כדי לשמור קוד משותף אחד לדפדפן ולדסקטופ.
- עבור העדכונים: נשקל הורדה/התקנה אוטומטית מלאה ללא אישור משתמש — נדחה לטובת מודל "בדוק → הורד (בלחיצה) → התקן (בלחיצה)" כדי לשמור שליטה ביד המשתמש ולמנוע עדכון/איתחול בלתי צפוי באמצע שימוש.

### השלכות
- נוספה תלות ריצה חדשה: `electron-updater` (ב-`dependencies`, נארזת בפועל ב-`app.asar` — אומת עם `asar list`).
- נוספו מפתחות `localStorage` חדשים: `taharahLocation`, `taharahZoom`, `taharahNotifications`, `taharahLastNotified`, `taharahAutoLaunch`. `wipeAll()` (מחיקת כל הנתונים) מנקה את כולם **מלבד** `taharahZoom` (הגדרת תצוגה, לא נתון אישי — נשאר בכוונה אחרי איפוס).
- `main.js`/`preload.js` הורחבו משמעותית: IPC חדש לניהול מגש/הפעלה אוטומטית ולבדיקת/הורדת/התקנת עדכונים.
- גרסת האפליקציה עודכנה ל-1.2.0 (שינוי פיצ'רים משמעותי, לא רק תיקוני באגים).
- אריזת `npm run dist` המלאה (כולל התלות החדשה והאייקון המתוקן) אומתה בפועל מקצה לקצה: build הצליח, `asar list` אימת הכללת `electron-updater` ו-`icon.png`, קובץ ה-exe שנוצר הורץ ונשאר פעיל עם כותרת חלון נכונה.

### מגבלות בדיקה שזוהו (לשקיפות)
- לא בוצעה לחיצה ידנית בפועל על אייקון מגש המערכת (Tray) או על כפתורי תפריט המגש — כלי האוטומציה הזמינים בסשן זה (דפדפן + PowerShell) אינם תומכים באוטומציה של רכיבי Tray native ב-Windows. נבדק בעקיפין: התהליך עולה ללא קריסה/דיאלוג שגיאה, קוד ה-IPC נבדק תחבירית ונטען בהצלחה.
- לא בוצעה בדיקת "בדוק עדכון" אמיתית מול GitHub מכיוון שלא פורסמה אף גרסה במאגר עדיין — הקוד נבדק לוודא שהוא לא קורס כאשר `window.api` לא קיים (דפדפן) ומציג הודעה מתאימה.
