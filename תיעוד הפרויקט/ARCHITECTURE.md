# ארכיטקטורה — לוח טהרת המשפחה

## סקירה כללית

אפליקציה כפולה:
1. **ווב/PWA** — קבצים סטטיים (index.html + js/), רץ בדפדפן, כל הנתונים ב-localStorage.
2. **תוכנה למחשב (Electron 25)** — אותו קוד רנדרר + תהליך ראשי (`main.js`) המוסיף: הצפנת PIN מקומית, OAuth לגוגל, וגיבוי אוטומטי לשיטס.

## מנוע החזקה (`js/chazaka.js`)

המנוע אינו מחשב תאריכים — הוא עונה על "**מה נקבע**": אילו ראיות נספרות לחזקה, ואיזו וסת
קבועה הוקבעה מהן. התאריכים נגזרים ממנו ב-`calculations.js` (`projectFixedVeset`).

```
db (localStorage)
   │  כל ראייה נשלפת עם kind · durationDays · closedFountain
   ▼
analyzeChazaka(reiyot)
   ├─ classifyReiyot()      → counted[] / excluded[] / warnings[]
   ├─ trailingSameDayRun()  → ג' ראיות באותו יום ובאותה עונה  → וסת חודש קבוע
   └─ trailingEqualSpans()  → ד' ראיות בג' הפלגות שוות        → וסת הפלגה קבוע
   ▼
calculateEngine(db, isOrZarua, {chazaka})
   ├─ אין וסת קבוע → שלושת החששות לכל ראייה (כתמיד)
   └─ יש וסת קבוע → החששות הרגילים נכתבו ל-computed.suppressed
                     והלוח מסומן ב-projectFixedVeset() בלבד
```

- **החרגות מהספירה:** `kind === 'ones'` (אונס/קפיצה) אינה נספרת; ראייה שסומנה כהמשך דימום
  נספרת עם קודמתה (אם מספר הימים מאפשר), ואחרת נספרת כראייה נפרדת ונרשמת `warning`.
- **קודי סימון:** `וק"ח` / `וק"ח*` / `וק"ה` / `וק"ש` / `וק"מ` / `וק"ד` — נפרדים מקודי החשש
  הרגיל (`עו"ב`, `עו"ל`, `עו"ה`, `יו"ח`), כדי לראות בלוח מהו זמן הוסת הקבוע.
- **וסת השבוע (`trailingSameWeekdayRun`):** ג' ראייות באותו יום בשבוע ובאותה עונה, **בהפרש של
  שבוע בדיוק** → `kind: 'week'` (`weekday` / `weekdayLabel`), ומוקרן כל שבעה ימים ב-`וק"ש`.
  הזיהוי מזניח במכוון זהות-יום-בשבוע בלא הפרש שבוע — ראו `docs/DECISIONS.md`.
- **יו"ח בחודש חסר — שלושה תאריכים:** `וק"ח*` מסמן אף את א' של החודש הבא ("בתורת ראש חודש")
  `[ד"ט | עמ' 4]`, מלבד כ"ט של החודש החסר ול' של חודש מאוחר.
- **עונות מעורבות (`mixedOnaChange`):** תבנית שנשלמה בעונה אחת והראייה שאחריה בעונה שכנגד
  (`[שט ל"ג | עמ' 112]`). היא **אינה** נקבעת כוסת קבועה (שאין שלש ראיות באותה עונה), ומקורה
  נוסף החשש שבעונה שכנגד — סימון `עו"מ`, מ-`calculations.js`, על אותו זמן וסת.
- **וסת לימים המתחלפים (`findAlternatingDays`):** שני ימי חודש שהפרשם שני ימים, ג' ראיות בכל
  אחד באותה עונה, והיום המפסיק שביניהם לא נראה כלל → `kind: 'mevucha'`, סימון `וק"מ`
  `[שט ל"ב | עמ' 107–108]`. הזיהוי צר במכוון — ראו `docs/DECISIONS.md`.
- **"צירוף למפרע" (`detectChiburLemafrea`):** "שראתה לל' ולל' ולכ' ושוב לל' אחר הכ' —
  קבעה לה וסת לל'... **כיון שוסת קצר אינו עוקר וסת הארוך**" `[שט ל"ג | עמ' 112]`. המועמד
  (ההפלגה האחרונה קובעת את האורך, ולפניה עוד שתי הפלגות שוות, כשהמפסיקות **קצרות** מהן וכל
  ראיות החלון באותה עונה) מוחזר תמיד ב-`chazaka.chibur`, והמנוע מסיק ממנו וסת **רק** כשהמתג
  `chiburLemafrea` דלוק — שהספר מגדיר את הכלל "רק לחומרא בעלמא ולא מעיקרא דדינא".
- **מועמדי וסת הדילוג (`detectDilugCandidates`):** המנוע מחזיר **תמיד** את מועמדי התבנית
  (`js/vesetDilug.js`) לתצוגה ולבירור עם רב, אך **אינו** יוצר מהם חשש אלא אם מתג החומרא
  `dilug` דלוק (`js/stringencies.js`) — מחמת אזהרת הספר מפני הריבוד המדומה `[ד"ט | עמ' 7]`.
- **אופק ההקרנה:** `CHAZAKA_HORIZON_DAYS` (730) — גבול **תצוגה** בלבד. הוסת הקבוע אינו
  פוקע מעצמו; עקירתו (ג' זמנים עם בדיקה כדין) ממומשת ב-`js/akira.js`, ומשעה שהושלמה
  הזמן הנעקר מסומן בלוח כנעקר ואינו מוצג עוד כחשש.
- **מתג:** `isChazakaEnabled()` ב-`storage.js` (`taharahChazaka`, דלוק כברירת מחדל); `app.js`
  מעביר אותו ל-`calculateEngine` דרך `engineOptions()` — נקודה אחת שממנה כל החישובים קוראים.
- **תצוגה:** `updateChazakaPanel()` ב-`ui.js` מציג את הוסת הקבוע, את הראיות שאינן נספרות,
  ואזהרות על נתונים סותרים; טבלת הריכוז מציגה שורת "נקבעה וסת קבועה" במקום להשאיר את
  המשתמשת לתהות אם החששות שבטבלה עוד נוהגים.

## מנוע משיכת הראייה (`js/reiyaDuration.js`)

מודול טהור וחסר-תלויות: אינו נוגע בלוח ואינו מחשב תאריכים — הוא עונה רק על שאלת
**העונות של הראייה**.

```
raiya (db): closureFountain === false + durationDays
extra = durationDays - 1
extra == 0   → [ona]                    extra >= 4 → [ona]  (א"צ לחוש אלא לתחילת הראייה)
אחרת        → [ona] + extra עונות סמוכות
```

- **מי נושאת את מספר הימים:** הקלט ("נמשך ברצף" + משך) נרשם על הראייה המאוחרת, אבל
  המניין נמדד מן הראייה **שבה החל הדימום**. הייחוס נעשה ב-`calculations.js`
  (`durationDaysByStartAbs`, דרך `exclusion.mergedInto`), והמודול אינו מכיר את הנתונים.
- **מה המנוע עושה בו:** `addForSighting` / `orZaruaForSighting` מפיצים כל חשש של הראייה
  (עו"ב, עו"ל, יו"ח, הפלגה, ואור זרוע) על כל עונותיה — עם הנוסח המסביר בלוח
  (`משיכת הראייה — חוששת גם לעונה הסמוכה`). אין קוד סימון נפרד: זהו אותו חשש בעונה נוספת.
- **התוספת היא תוספת בלבד:** המנוע אינו מסיר חשש ואינו נוגע ברשומת הראייה עצמה.
- `MAX_EXTRA_ONOT = 3` — כלומר הדימום המרבי שעדיין מוסיף עונות הוא ארבעה ימים.

## מתגי החומרא (`js/stringencies.js`)

כל מקום שבו הספר מביא **שתי שיטות** — ההכרעה אינה של הקוד: ברירת המחדל היא השיטה
הפשוטה, וכל חומרא מופעלת במתג מפורש וביודעין (עיקרון "הצגת הדין המדויק בלבד",
`docs/DECISIONS.md`).

```
STRINGENCY_DEFS   →   { key, label, hint, text (לשון המקור), source, default }
      │
      ├─ js/storage.js: getStringencies() / saveStringencies()   (הגדרה — אינה בגיבוי)
      ├─ js/app.js: renderStringencySettings() — מסך ההגדרות נבנה מן המודול
      └─ calculateEngine(options.stringencies) → normalizeStringencies()
              ├─ safekOnaBoth        → לחוש לשתי העונות בספק עונה
              ├─ dilug               → וסת הדילוג והסירוג (`js/vesetDilug.js`)
              ├─ checkUprootNonFixed → דרישת בדיקה בעקירת וסת שאינו קבוע
              ├─ orZaruaDay31        → עונת אור זרוע בליל יום הל"א
              ├─ lateBedika          → בדיקה באיחור מועילה (הב"י)
              ├─ haflagahFromEnd     → מניין ההפלגה מסוף הראייה
              ├─ chiburLemafrea      → קביעת ההפלגה הארוכה על פני הפלגה קצרה (צירוף למפרע)
              ├─ stainUproots        → כתם בזמן הוסת נחשב עקירה (שערי טוהר)
              └─ frightBedika        → פחד פתאום תובע בדיקה (הגר"ש קלוגר)
```

- **מתג חסר = ברירת המחדל של המודול** — ולכן הוספת מתג אינה דורשת הגירת נתונים.
- **המתגים אינם נשמרים בגיבוי גוגל**, כשאר ההגדרות (מנועים, מצב חיים, מיקום): הם בחירת
  מנהג מקומית ולא נתוני תיעוד.
- כל שינוי מחיל חישוב מחדש (`refreshCalendar()`); ומתג שאינו מוכר מדולג בשקט.

## זמני נץ ושקיעה (`js/zmanim.js`)

מודול **תצוגה בלבד** לגבי הדין עצמו — הוא מספק את מה שהדין תולה בו — "ואם ראתה סמוך
לנץ החמה או שקיעתה ומסופקת מתי התחילה ראייתה" `[ד"ט | עמ' 1]` — ואינו קובע עונה ואינו
מוסיף חשש. (מ-2026-09-22 הוא כן קובע איזה **תאריך עברי** הוא "היום" — ראו להלן —
אך זו שאלה של שעון, לא של דין.)

```
getSavedLocation()   (הגדרה; ברירת המחדל: אין מיקום)
      │
      ▼
rawDayTimes(abs, location)             ← hebcal: Zmanim(date, lat, long)  (פנימי, Date גולמי)
      │
      ├─→ dayTimes(abs, location) → מעוצב לתצוגה
      │      ├─ day   → הנץ והשקיעה של אותו תאריך לועזי
      │      └─ night → שקיעת היום הלועזי שלפניו + הנץ של אותו יום
      │      ▼
      │   timesLine() → מודאל פרטי הראייה · renderDayPrishaHint() של מודאל היום
      │
      ├─→ effectiveTodayAbs(location, now) → "היום" לפי שקיעה, לא חצות אזרחי
      │      (ראו js/app.js · js/ui.js: currentTodayAbs())
      │
      └─→ elapsedOnotOf(abs, location, now) → {night, day}: אילו עונות של abs כבר חלפו
             (ראו js/ui.js: renderBaseDashboard — סינון התראת "היום עונת פרישה")
```

- **בלא מיקום אין זמנים** — ואין בכך שינוי בדין: העונה נשארת בחירת המשתמשת, והחומרה
  של לחוש לשתי העונות היא מתג (`safekOnaBoth`). `effectiveTodayAbs`/`elapsedOnotOf`
  חוזרות אז בדיוק להתנהגות הישנה (חצות אזרחי, בלי סינון עונה) — עקרון זהה בלשון קוד.
- **עונת הלילה של תאריך עברי קודמת ליום שלו** — ולכן שקיעתה נלקחת מן היום הלועזי שלפניו,
  כמו בעונת אור זרוע: "אם הוסת בעונת יום — חוששת לעונת הלילה שלפניו".
- הרשימה סטטית (16 מוקדים) — אין geocoding מקוון, שהאפליקציה אינה פונה לרשת אלא לגוגל שיטס.
- **"היום" לפי שקיעה (`effectiveTodayAbs`):** היממה העברית נפתחת בשקיעה. כש**יש**
  מיקום שמור, ברגע שהשקיעה של התאריך האזרחי הנוכחי חלפה — "היום" מתקדם לתאריך העברי
  הבא, אף שהחצות האזרחי עוד לא הגיע. `js/app.js: currentTodayAbs()` ו-`js/ui.js:
  currentTodayAbs()` (שתי עטיפות מקבילות — `ui.js` נטען גם בבדיקות Node בלי
  `localStorage` אמיתי, ולכן עוטפת ב-`try/catch`) הן נקודת הקריאה היחידה; הן
  מחליפות כל `new HDate().abs()` שייצג "היום" ב-`app.js`/`ui.js` — כולל
  `engineOptions()` (המנוע עצמו), סימון "היום" בלוח, ברירת המחדל של
  `updateDashboard`, ורשימת תקופות הכדורים. **`js/calculations.js` אינו נוגע בכך:**
  ברירת המחדל הפנימית שלו (`new HDate().abs()`) נשארה בכוונה — המודול מתועד כטהור
  וניתן-לבדיקה, ומקבל `today` כפרמטר מוזרק; `app.js` הוא שמזריק את הערך הנכון.
- **עונה שחלפה (`elapsedOnotOf`):** עונת הלילה של `abs` יכולה לחלוף עם הנץ **בלי**
  ש-`abs` עצמו יתקדם (זה קורה רק בשקיעה) — ולכן התראת "היום עונת פרישה!" בדשבורד
  (`js/ui.js: renderBaseDashboard`) מסננת לפי כך: פרישת לילה שהנץ שלה כבר עבר, או
  פרישת יום שהשקיעה שלה כבר עברה (מקרה תיאורטי בלבד בזרימה הרגילה, כי או-אז `abs`
  כבר התקדם), אינן מוצגות יותר כהתראת "היום".

## סימוני היום (`js/dayMarks.js`)

מודול **הגדרה ונגזרות בלבד** — אינו מחשב תאריכים ואינו נוגע בלוח. הוא עונה על שאלה אחת:
**מה נסב על היום עצמו ולא על האירוע שבו**. חמישה דינים נמנים כאן: כתם · פחד פתאום
(ביעתותא) · חרדה מתמשכת · יציאה לדרך / בא מן הדרך · ליל החופה / בעילת מצוה.

```
DAY_MARKS               → [{ code, label, help, source }]  — מקור אחד לרשימה, לתפריט ולסימון על הלוח
DAY_MARK_RULES          → { title, text, source } לכל דין — לתצוגה בפאנל ובכרטיס ההסבר
entry.marks[] (db)      → סימונים על כל סוג רשומה (ראייה / הפסק / בדיקה / רשומה ריקה)
   ├─ marksByDay(db)       → Map<abs, string[]>
   └─ stainDays(marks)     → Set<abs> — ל-js/akira.js (עקירה מחמת כתם)
                              ▼
orZaruaExemptionFor({ shiftAbs, shiftOna, marks, tevilot })
   ├─ lilTvila  → עונת הלילה של יום שהטבילה שלו תועדה  ("מותרת, ותבדוק קו\"ת")
   ├─ chuppah   → סימון על אותו יום, בעונת לילה
   └─ travel    → סימון על אותו יום (כל עונה) — והוא הדין בבא מן הדרך
                              ▼
calculateEngine → orZaruaExemptions[] · stainAbs · dayMarks · fright
     │                  │                 │            │
     │                  │                 │            └─ fright.open / settled / anxietyDays
     │                  └─ js/akira.js (מתג stainUproots)
     └─ לא יוצאים לפלט בשקט: כל עונה שנפטרה מוצגת בפאנל עם הטעם ומראה מקומה
```

- **הסימון אינו "סוג אירוע"** — יום יכול להיות גם יום ראייה וגם יום יציאה לדרך, ולכן
  הסימונים הם **רשימה** על רשומת היום (`entry.marks`), בכל סוג רשומה. קוד מוכר בלבד
  נשמר, וקוד שאינו מזוהה כבר אינו נמחק בשקט — הוא נשמר ומוצג.
- **`addOrZarua` / `isOrZaruaExempt` מחליפים את `applyOrZarua` בכל מקום שהדין נוהג בו**
  — כולל עונת יום הל"א ועונות משיכת הראייה — וכך אין מסלול שמוסיף עונת אור זרוע בלי
  לעבור בפטורים.
- **מה שאינו פטור נשאר חשש:** ליל שבת · העונה שלפני יום הל' · יום ל"א (מתג);
  וליתר דיוק — החששות של יום ההפסקה בכדורים ושל ראייה שסומנה כמחמת כדורים מדלגים
  על אור זרוע בנפרד (`js/pillPause.js`).
- **פחד פתאום:** `fright.open` = ימים שטרם נבררו (לא היתה בהם ראייה ולא בדיקה כדין);
  קינוח לבד מסומן `wipeOnly` ואינו מברר `[שט מ"א | עמ' 182]`. במתג `frightBedika`
  נכנסת לכל אחד מהם דרישת בדיקה מתוארכת (`pendingChecks`, `kind: 'fright'`, קוד `בהלה`).
- **חרדה מתמשכת היא מידע ולא דין מבטל:** היא מוצגת בפאנל, ואינה מסירה חששות של ראיות
  שתועדו — שהרי הדין נאמר על טבע הדמים ("דאגה ופחד שאינו בא פתאום" `[שט כ"ז | עמ' 42]`).
- **תצוגה:** כל סימון נכתב על גבי היום עצמו בלוח (`buildDayMarksMarker`, `js/ui.js`),
  והפאנל `updateDayStatePanel()` (`#day-state-container`) מציג את מה שאין לו יום לסמן עליו
  — הפטורים שנסתלקו (עם הטעם ומראה המקום), ואת מצב הבהלה שטרם נבררה.

## מנוע וסת הגוף (`js/vesetGuf.js`)

מנוע החזקה מזהה וסתות של **ימים**. מודול זה מזהה וסתות של **גוף**: המיחוש שתועד על הראייה
(`signs[]`), המיחוש שתועד **בלא ראייה** (`signRecords`), והצירוף של היום והמיחוש.

```
db (localStorage)
   │  כל ראייה נשלפת עם signs[] (קודי BODY_SIGNS)
   │  וכל רשומה שסומנה standaloneSign (type: 'sign' / בדיקה שנספח אליה מיחוש)
   ▼
analyzeBodyVeset({ reiyot, counted, signRecords })
   ├─ bySign                → לכל מיחוש: מניין הראיות → fixed (ג') / pending (א'–ב')
   ├─ trailingSignRun()     → ריצף רצוף של אותו מיחוש (קוטע: ראייה בלא המיחוש)
   ├─ findCompoundVesets()  → וסת מורכב: ג' באותו יום בחודש / ד' בהפלגות שוות — עם המיחוש
   ├─ standaloneSigns[]     → מיחוש בלא ראייה: נספר לקביעות, ותובע בדיקה מתוארכת
   └─ unauditedSigns[]      → מיחוש על ראייה שאינה נספרת (אונס / המשך) — מדווח, לא קובע
   ▼
calculateEngine(...)
   ├─ חשש הווסת המורכב נכתב ל-computed.prishot בקודים ומ"ח / ומ"ה (בלי עונת אור זרוע)
   ├─ וסת ימים זהה שראיותיה כולן במיחוש מוחלפת בו (computed.suppressed, why: 'compound')
   ├─ זמני הבדיקה של הווסת המורכבת → computed.pendingChecks עם kind: 'body' (בכל מצב)
   └─ bodyVeset בתוצאת המנוע → פאנל `updateChazakaPanel()` + סימון `מיחוש` על יום הראייה
   ▼
bodyReminder({ bodyVeset, prishot, pendingChecks, today })   ← נקודת ההצגה היחידה
   ├─ pending → כרטיס אדום בראש המסך + התראת toast (פעם ביום, אחרי הפתיחה)
   │            — ובו שתי עילות: זמן וסת מורכבת שעבר, או מיחוש בלא ראייה שלא נבדק (עם תאריכו)
   ├─ today   → "היום יום הווסת המורכבת" — והבדיקה הנדרשת בו
   └─ armed   → בלוק שני בכרטיס היום: המיחוש שתועד והבדיקה הנדרשת כשתבא
```

**זרימת התזכורת היומית (וסת הגוף בהתראות):**

```
computed.pendingChecks (kind: 'body')     ──┐
computed.prishot[today] = ומ"ח / ומ"ה     ──┼─→ bodyReminder() → updateDashboard()
bodyVeset.bySign                          ──┘        │
                                                       ├─ כרטיס ראש המסך (dash-red / dash-body)
                                                       ├─ announceBodyReminder() באפליקציה
                                                       │    → toast פעם ביום (localStorage)
                                                       └─ renderDayPrishaHint() במודאל היום
```

- **התזכורת מציגה, ואינה מחדשת דין:** כל שכבה כאן היא ניסוח של מקור, ומראה המקום מודפס
  לצידה. `pending` קודם לכל, מחמת "אסורה לבעלה עד שתבדוק" `[שט כ"ד | עמ' 7]`,
  "ולהלכה כך אף בוסת הגוף שאינה קבועה" `[שט ל"ט | עמ' 160]`, ובבדיקה כדין `[שט מ"א | עמ' 182]`.
- **ההתראה הקופצת היא יומית ולא בכל פתיחה:** יום שכבר הוצג נשמר ב-`taharahBodyReminderSeen`
  (`getBodyReminderSeen` / `setBodyReminderSeen` ב-`js/storage.js`), והיא אינה מוצגת לפני פתיחת
  היומן (מסך נעילה / מסך הקמה).
- **מיחוש שעומד ותו לא אינו מצדיק התראה קופצת** — אין בו חידוש של היום, והוא ממילא בכרטיס.
- **למיחוש שתועד יש תאריך — ולתביעה שלו יש מועד:** רשומת מיחוש בלא ראייה
  (`standaloneSign`) נושאת את היום שבו בא המיחוש, וממנו נמדדת "אסורה עד שתבדוק"
  `[שט ל"ט | עמ' 158]`; ואילו **הווסת המורכבת** (יום + מיחוש) היא וסת של זמן, ולכן זמנה
  שעבר בלא בדיקה נכנס למניין — "שצריכה לחשוש באותו היום אף קודם שבא המיחוש" `[שט כ"ז | עמ' 49]`.
- **מיחוש בלא ראייה נספר, אך אינו עושה וסת מורכבת:** אין לו יום קביעות, וצירוף שני מיחושים
  כאלה אינו חזקה — ולכן רשימת המיחושים בלא ראייה נכנסת לחשבון ה-`bySign` בלבד ואינה נכנסת
  ל-`findCompoundVesets` (שם עוברים רק עברי הראיות).
- **התביעה אינה מסתלקת מפני וסת קבועה של ימים:** זמני הבדיקה של וסת קבועה מגיעים מ-`akirot`
  בלבד, ולכן זמני הבדיקה של הווסת המורכבת נבנים בנפרד מן החששות המסומנים ב-`establishedConcern`
  ומצורפים ל-`pendingChecks` בכל מצב. `bodyReminder` קורא להם לפי `kind: 'body'` בלבד.
- **התנאי מגיע מן המשתמשת:** המודאל דורש אישור שהמיחוש "משונה — לא דבר שבשיגרה — וברור שהוא
  קשור לראייה" לפני שנפתחת רשימת הסימנים.
- **הווסת המורכב אינו מבטל חששות** (עונה בינונית נשארת `[שט ל"ט | עמ' 165]`), ולכן אינו נכנס
  ל-`standingVesets`; הוא מוסיף סימון ואינו מפעיל את מסלול ההחלפה של וסת קבוע.
- **`establishedConcern`:** חשש של וסת מורכבת מסומן בדגל, כדי שתעבור את מסלול העקירה של
  חששות שאינם קבועים בשלום (וסת שנקבעה אינה נעקרת במעבר זמן בודד).

## מנוע העקירה (`js/akira.js`)

מנוע החזקה עונה "מה נקבע"; מנוע העקירה עונה "מה פקע". הנתונים שלו מגיעים משני מקומות:
הראיות (`reiyot`) ורשומות ה**בדיקה** (`type: 'check'`).

```
db (localStorage)
   │  extractChecks(db) → [{abs, ona, depth: deep|wipe}]
   ▼
analyzeAkirot({reiyot, established, lastCounted, checks, today, project})
   ├─ evaluateDueTimes()   → 'seen' | 'checked' | 'pending' | 'upcoming' לכל זמן וסת
   │                         3 זמנים רצופים שנבדקו כדין → נעקר
   ├─ periodsToClear(span) → span*3-2 ימים בלא ראייה → עקירת ההפלגה
   └─ sightingsMatchingVeset() → מחלוקת חזרת הוסת (מוצגת, לא מוכרעת)
   ▼
calculateEngine(...)  →  uprooted / active  +  computed.pendingChecks
```

- **בדיקה מכסה זמן וסת** אם נעשתה בו ביום או אחריו, לפני זמן הוסת הבא של אותה וסת,
  ובלבד שלא הייתה ראייה בינתיים; בדיקה באותו תאריך נדרשת להיות באותה עונה.
- **עיכוב עקירה בכדורים:** `pillsDays(from, to)` מחזיר כמה ימים היו בתוך תקופת נטילה,
  והם אינם נמנים למניין החזור; `isPillSighting()` מסנן ראיות שסומנו כמחמת כדורים מן
  ה„בלא שראתה” ומן הבדיקה של חזרת הוסת `[ד"ט | עמ' 8]`. שני הפרמטרים אופציונליים, ומי
  שאין לו מצב חיים — מקבל את ההתנהגות הקודמת בדיוק.
- **עקירה מול התרת הבעל הן שתי מסקנות נפרדות:** העקירה יכולה להיות אוטומטית (וסת
  שאינו קבוע), ובכל זאת `computed.pendingChecks` תמשיך להתריע עד שתירשם בדיקה.
- **המנוע מקבל את פונקציית ההקרנה בהזרקה** (`project`) — הוא אינו מייבא את
  `calculations.js`, כדי שלא ייווצר מעגל יבוא (calculations → akira/calculations).
- **מה שנעקר מסומן בלוח בעמימות** ולא נמחק (`p.uprooted = true`), וב-`computed.uprooted`
  הוא מדווח לפאנל.

## מנוע מצב החיים (`js/lifeState.js`)

שני המנועים הקודמים עונים "מה נקבע" ומה" פקע", ושניהם מניחים שאין ידע על מצב האישה.
מנוע מצב החיים מספק את הידע הזה, וממנו נגזרות שלוש מסקנות שהן בחינה של **חובות**
(ולא תאריכים) — ולכן הוא מוצג בפנל משלו, עם השיעור והמקור.

```
הגדרות (localStorage: taharahLifeState)
   ├─ pregnancyAbs · birthAbs · nursing · nursingLenient · ageYears · pills[]
   ▼
analyzeLifeState({life, reiyot, today})
   ├─ silek / silekSinceAbs   → מסולקת דמים, וממתי
   ├─ exemptFromCheck         → פטור מבדיקה [שט כ"ה | עמ' 17–18]
   ├─ pills.daysBetween()     → כמה ימים היו בתוך נטילת כדורים
   └─ statuses[] / notes[]    → השיעור, המקור, והמחלוקות שלא הוכרעו
   ▼
calculateEngine(...)  →  suppressed (why: 'silek') · checkExemption · standingVesets
                     →  akirot.pillsDays / isPillSighting (עיכוב עקירה)
```

- **חששות שהיו לה קודם הסילוק — מבוטלים, אך מדווחים:** חששותיה של כל ראייה שעד
  `silekSinceAbs` נכתבים ל-`computed.suppressed` עם `why: 'silek'`; וסת קבוע שנקבע מן
  הראיות שלפני הסילוק אינו נוהג ("מעוברת ומניקה אינה חוששת לוסתה הראשון אפילו היה לה
  וסת קבוע" — שו"ע סל"ד).
- **`standingVesets`:** תוצאת המנוע נושאת את רשימת הוסתות העומדות בפועל, לאחר עקירה
  **ואחרי** סילוק. ה-UI מחויב לקרוא לזו ולא `akirot.active` — אחרת יכריז על וסת שהמנוע
  כבר אינו מחיל.
- **הסילוק אינו מבטל את הדין לכל עת:** בזמן הסילוק אין פטור מחששות חדשים — **ראייה
  שבתוך הסילוק מחזירה את הדין** ("שראתה בזמן הסילוק... חוששת לה כדין וסת שאינו קבוע"):
  וסת החודש, ועונה בינונית כמחלוקת, והפלגה רק משתי ראיות ששתיהן בתוך הסילוק.
- **מניין חודשי הלוח:** `addHebrewMonths()` ספר החודשים **בחודשי לוח**, ולא במניין ימים,
  כולל הגבלת היום לסוף החודש. זה נצרך לשיעור כ"ד חודש של הלידה (`NURSING_MONTHS`).
- **שבוע הריון ותאריך לידה משוער (`pregnant.gestationalWeek` / `pregnant.dueDateAbs`,
  2026-09-22):** הערכה כללית **ולא** מקור הלכתי ולא קביעה רפואית —
  `PREGNANCY_ESTIMATED_TERM_DAYS = 266` יום מ"תחילת ההריון" (השדה הקיים, שהוא תאריך
  ליל הטבילה/התעברות ולא תחילת מחזור). מוצג ב-`updateLifePanel` (`js/ui.js`) רק כל
  עוד לא נרשמה לידה, עם לשון "משוער" ואזהרה מפורשת. אינו נכנס לשום חישוב הלכתי —
  שדה תצוגה בלבד.
- **מצב החיים הוא הגדרה ולא רשומה:** אינו נשמר בגיבוי גוגל (כמו מתגי המנועים), ושרידתו
  היא ב-localStorage של המכשיר. `wipeAll()` מוחק גם אותו.
- **מתג כללי:** `enabled: false` משמעו "לא הוגדר דבר" — ההתנהגות חוזרת בדיוק למצב שלפני
  המנוע. כלומר כל הקלה מופעלת במודע, ואינה ברירת מחדל סמויה.

## מנוע החזרה מן הסילוק (`js/silekReturn.js`)

שלושת המנועים הקודמים עונים "מה נקבע", "מה פקע" ו"מה מצב הסילוק". המנוע הזה עונה על
השאלה שנשארה: **מה קורה כשהסילוק תם** — לאיזו וסת היא שבה, וממתי. התשובה תלויה בסוג הוסת:
וסת הימים שבה **מיד**, ווסת ההפלגה אינה שבה עד שתראה `[שט כ"ט | עמ' 71]`.

```
analyzeLifeState(...) → dormancy.windows [{fromAbs, untilAbs}]
   │  הריון: מהצום עד הלידה · לידה והנקה: כ"ד חודש · זקנה/קטנה: חלון פתוח
   ▼
returnInterlude(life, today)
   │  תקופת ההשהיה: תום הסילוק — ואם לא היה סילוק, הפסקת הכדורים ("וכדין מעוברת ומניקה")
   ▼
analyzeSilekReturn({reiyot, life, today})
   ├─ analyzeChazaka(ראיות שלפני ההשהיה)  → הוסת שהיתה לה קודם
   ├─ וסת הימים   → restored, עם restoredFromAbs (מיד)
   └─ וסת ההפלגה → restored עם restoredAnchorAbs = הראייה הראשונה שאחרי הסילוק,
                      ואם אין כזו — waiting (אינה נדרשת עד שתראה)
   ▼
calculateEngine(...) → silekReturn · standingVesets (עם העוגן החדש)
```

- **החלון מול המצב:** `dormancy.active` = הסילוק נמשך; `dormancy.ended` = היה סילוק ותם;
  `dormancy.upToAbs` = הגבול שעד אליו חששותיה של ראייה מבוטלות (מראשית הסילוק בעודו נמשך,
  ומסופו משהוא תם).
- **`disqualifiesEstablishment(abs)`:** מה אינו ראוי להעמיד וסת — כל מה שלפני הסילוק (הרי היא
  שבה לוסת שהיה לה אז), וראייה שבתוך סילוק שנסתיים ("לא קבעה לה וסת בראיות שראתה בימי
  הסילוק" `[שט כ"ט | עמ' 71]`).
- **הוספה מחדש — לא שינוי של הראיות:** הוסת שחזרה נכתבת לרשימת הניתוח עם
  `restored: true` / `restoredFromAbs` / `restoredAnchorAbs`, וה"תאום" הישן מוחלף ונרשם
  ב-`computed.suppressed` (`why: 'restored'`) — כדי שלא יעמדו שני זמנים לאותו יום.
- **וסת מחמת כדורים:** וסת שכל ראיותיה מן התקופה שאחרי תחילת הנטילה מוחלפת בוסת שחזרה
  (`why: 'pills'`) — "אחר שהפסיקה חוזרת לוסתה הראשון" `[שט כ"ז | עמ' 42]`.
- **שני וסתות מאותו סוג** (שחזרה ונקבעה אחרי הסילוק) — שתיהן מוצגות, עם סימון מחלוקת.
  המנוע אינו מסיר חובה על דעת עצמו.
- **ההקרנה:** `projectFixedVeset` קיבל `options.fromAbs` (התחלת ההקרנה מתום הסילוק — אחרת
  המופע הראשון שאחריו נדלג, ואף האופק נמדד קודם), ו-`analyzeAkirot` קיבל `anchorOf(veset)`.

## מנוע יום ההפסקה בכדורים (`js/pillPause.js`)

מנוע באותו מעמד: **אינו** מחשב תאריכים ואינו מחזיק וסת קבועה. הוא עונה על שאלה אחת — מה
חוששת האשה **בהפסקת כדורים** — ומחזיר רשומות פרישה שהמנוע מוסיף ללוח.

```
life.pills.periods [{startAbs, endAbs}]
   │  "ההפסקה" = סופה של כל תקופה שנרשמה (endAbs !== null, ולא בעתיד)
   ▼
analyzePillPause({life, reiyot, today})
   ├─ لكل הפסקה: יום הפסקה = endAbs; יום א' (endAbs+1) — מותר; ימים ב'–ה' — חשש
   ├─ establishedBefore → הימים שקבעה לעצמה (מראיות שאחרי הפסקות **קודמות**)
   │     ראיה אחת → וסת שאינו קבוע · ג' פעמים באותו יום → "קבועה" שאינה גמורה
   └─ concerns[] + notes[] (עם מקורות)
   ▼
calculateEngine(...) → computed.prishot (סימון פה"כ) · pillPause · pendingChecks לא כולל
```

- **החששות מוזרקים אחרי חישוב הבדיקות** ולכן אינם יוצרים "אסורה עד שתבדוק": לשון הספר
  "להחמיר לפרוש". הם גם אינם מבטלים חששות אחרים — וסת מכדורים אינה קבועה גמורה `[שט כ"ז | עמ' 41]`.
- **עונה לא מבוררת:** מסומנות שתי העונות (יום ולילה); משהוקבע לה יום — העונה שבה ראתה.
- **פטור מאור זרוע (A7):** `calculations.js` מדלג על `applyOrZarua` גם לחששות של יום ההפסקה
  (הם נוספים אחרי החישוב) וגם לחששות של ראייה שסומנה כמחמת כדורים (`isPillSighting`) —
  "לעונת האור זרוע אין צריכה לחשוש" `[שט כ"ז | עמ' 40]`.
- **דילוג על סילוק אחר:** הפסקה שחלה בתוך חלון הריון/הנקה/זקנה/קטנה אינה מייצרת חשש
  (`life.dormancy.windows`).

## זרימת OAuth (תוכנה למחשב בלבד)

```
Renderer (googleBackup.js)
   │ window.api.oauthStart()
   ▼
Main (main.js): פתיחת דפדפן → http://127.0.0.1:8471 תופס code
   │ exchange → access+refresh token (+ userinfo לאימייל)
   ▼
userData/google-oauth-store.json  (טוקנים, email, sheetId, lastBackupAt)
userData/oauth-debug.log          (רשומת כל שלב OAuth — לניפוי כשלים בדיעבד)

fetch של הרנדרר ל-sheets.googleapis.com ← main מצרף Authorization
(דרך webRequest.onBeforeSendHeaders, בכתובות גוגל בלבד)
```

- **פרטי OAuth מוטבעים באפליקציה** (`OAUTH_DEFAULT_CLIENT_ID` / `OAUTH_DEFAULT_CLIENT_SECRET` ב-`main.js`) — המשתמש רק לוחץ "חבר חשבון גוגל", בלי פרויקט גוגל ובלי להזין סוד. הקוד קורא אותם בכל שימוש ולא פעם אחת בטעינה, כדי שעקיפה מקומית תיכנס לתוקף מיד; העקיפה היחידה היא `google-oauth.local.json` (מוחרג מ-git, **אינו נארז**) ואם היא חסרה/ריקה — נפילה חזרה למובנה. `userData/google-oauth-client.json` (מהזנת הסוד בממשק בגרסאות קודמות) **אינו נקרא יותר** — סוד ישן שם היה דורס את המובנה. ראה `GOOGLE_OAUTH_SETUP.md`.
- **בקשות רקע לשרת ה-loopback** (כמו `favicon.ico`) מקבלות 404 ואינן מסיימות את הזרימה — בעבר הן זוהו כ"אין code" והציגו שגיאה על התחברות שכבר הצליחה.
- **ערוצי IPC של גוגל**: `oauth-start`, `oauth-status`, `oauth-ensure-token`, `oauth-set-meta`, `oauth-disconnect`, `oauth-open-sheet` (הערוץ `oauth-save-credentials` הוסר יחד עם שדה הסוד בממשק).
- היקפים: **`drive.file` בלבד** — היקף `Non-sensitive`. `spreadsheets.create` / `values.update` / `batchUpdate` מקבלים אותו, ואילו ההיקף הרגיש `spreadsheets` הוסר כי הוא מחייב אימות גוגל ומציג אזהרה למשתמשים.
- בווב/PWA הכרטיס מוסתר וכל ה-APIs מזוהים לפי היעדר `window.api`.

## גיבוי לשיטס

- גיליון אחד למשתמש: "לוח טהרת המשפחה - גיבוי", גיליון "Backup" עם כותרת קפואה.

- **עמודה 8 (H) — "קוד גיבוי" ו"סימוני היום" חולקות עמודה אחת.** בשורת המטא-נתונים
  יושב בה קוד הגיבוי (שש ספרות), ובשורות הנתונים — תוויות הסימונים. הפרסור מסנן
  לקודים מוכרים בלבד, ולכן **גיליון שנכתב לפני הוספת הסימונים נשחזר כתקין** ואינו
  מייצר סימונים מדומים מתוך הספרות.
- סוגי האירועים: `reiyah` (עם `kind` / `durationDays` / `closedFountain` / `signs[]`), `hefsek`, `tevilah`,
  ו-`check` (בדיקה: `ona` + `depth` — `deep` / `wipe`). סוג שאינו מזוהה מדולג בשחזור ולא מפיל אותו.
- **מיחושים (B2):** נכתבים כתוויות קריאות ("פיהוק / פצעים בפנים", מופרדות ב-`/`), ותווית שאינה
  מוכרת נשמרת כמו שהיא — כדי שלא יאבד תיעוד של מיחוש בשקט.

## היסטוריית גיבויים וטאב `היסטוריה`

הטאב הראשי (`Backup`) משקף את המצב **הנוכחי** ונכתב מחדש בכל גיבוי. לכן מתווסף טאב שני
`היסטוריה` — לוג מצטבר שכל שורה בו היא שינוי בודד:

```
חותמת זמן | מזהה | תאריך עברי | תאריך לועזי | סוג אירוע | עונה | הערה | פעולה | סוג הראייה | משך הראייה | מיחוש גופני | סימוני היום
```

- **כתיבה:** בכל גיבוי מושווה ה-db הנוכחי למצב שנשמר ב-`localStorage` (`taharahHistoryState`)
  דרך `diffDb`, ונרשמות רק השורות שהשתנו (`נוסף`/`עודכן`/`נמחק`). גיבוי בלי שינוי לא כותב דבר.
- **כשל בהיסטוריה אינו מפיל גיבוי** — כל מסלול ההיסטוריה עטוף ב-try/catch, והטאב נוצר לפי דרישה.
- **נקודות שחזור:** `parseHistoryRows` (עמיד לשורות פגומות/משתמש שערך ידנית) → `buildRestorePoints`
  שמריץ replay על הלוג ומחזיר תמונת מצב מלאה אחרי כל גיבוי, מהחדשה לישנה. המצב כולל מחיקות,
  ולכן ניתן לשחזר אירוע שנמחק.
- **מתוך הממשק:** כפתור "🕘 נקודות שחזור (היסטוריה)" בהגדרות → בחירת נקודה → אותו
  חלון מיזוג/החלפה של השחזור הרגיל (`mergeDb`).
- **כלי אימות:** `node tools/verify_google_history.mjs` — מריץ את כל הזרימה מול גוגל האמיתי
  על גיליון זמני שנמחק בסוף.
- כל גיבוי = ניקוי A2:I + הוספה מחדש (idempotent).
- טריגרים: ראשוני בחיבור, ידני, יומי (tick דקתי מה-main), ובעת שינוי נתונים (מוגבל ל-5 דקות).
- כשלי רשת: ניסיון חוזר 1 דק' → 5 דק' → 10, 20, 40... מקסימום 2 שעות.

## שחזור

שני מסלולים:

1. **מסך ההגדרה הראשונית או מסך הנעילה** → קריאת הגיליון → שחזור db + PIN + אימייל → reload. הסיסמה נשמרת בגיליון בטקסט ברור (החלטה מתועדת ב-DECISIONS.md).
2. **הגדרות (כפתור "שחזר מהגיבוי בגוגל")** — למשתמש שכבר בפנים. הזרימה: שליפת הגיליון → הצגת סיכום (כמה אירועים בגיבוי/במכשיר, כמה ייווספו, כמה קיימים רק במכשיר) → בחירה בין **מיזוג** (הפונקציה `mergeDb` — מוסיפה רק אירועים שחסרים מקומית ולעולם אינה מוחקת) ל**החלפה מלאה** → שמירה, ריענון, ודחיפה חזרה לגיליון. אין גיבוי חוזר אוטומטי: הזרימה חד-כיוונית.

## כלי עזר — `tools/`

`extract_hebrew_pdf.py` אינו חלק מהאפליקציה אלא כלי מחקר. הוא משחזר טקסט מספרי
מקור עבריים שנשמרו ב-PDF עם גופני subset ללא מיפוי Unicode תקני. השיטה:
קריאת טבלאות `/Differences` לשחזור שמות הגליפים העבריים; זיהוי קידודי
`cp1255`/`MacHebrew` שהוקלדו בקודי לטינית; קביעת כיוון הטקסט (לוגי/ויזואלי)
לכל גופן באמצעות מודל ביגרמות מהספר עצמו; והרכבת שתי עמודות בפריסה.
הכלי שיחזר את "שיעורי טהרה" (371,466 תווים) באופן הניתן לשחזור.

`verify_citations.mjs` אינו קורא PDF אלא מודד את **התיעוד עצמו**: הוא גוזר מן התמלול
את טבלת "איזה עמוד שייך לאיזה שיעור" (מתוך **כותרות השיעור שבגוף הספר**), ומאמת כל
מראה מקום מן הצורה `[שט N | עמ' P]` שבקוד ובתיעוד — ולצידם, במפורש, `[שט פרק N | עמ' P]`
לציטוט המכוון ל**פרק** (הספר מצטט בשתי מערכות מספור, ראו §0.3.1 ב-
`docs/SPEC_DINIM_VESATOT.md`). הוא מכיר גם את צורתם של ציטוטים
**שבתוך מחרוזות JS** (שם המפריד והגרש כתובים במילוט: `[שט כ\"ז | עמ\' 41]`) וגם ציטוטים
של כמה עמודים. המצבים: **דיווח** (ברירת מחדל, `npm run verify:sources`) · `--dry-run`
תצוגה מוקדמת של התיקון · `--fix` כתיבת התיקון · `--strict` כשל על כל אי-התאמה.

**מה שנמצא והוכרע (2026-09-17):** כל **עמוד** מתיישב עם התמלול, ומספרי ה**שיעורים**
הם שנתעו. תוקנו 223 ציטוטים (הסטה אחידה של שיעור אחד), ואחריהם — בסבב שני — **נסגרו 19
הציטוטים האחרונים, כל אחד לפי תוכן העמוד בתמלול** (שבעה הומרו למספר השיעור של העמוד,
שלושה סומנו `פרק`, שני טווחים החולשים על גבול שיעור אומתו בלא שינוי, ואחד היה חסר מספר
ונוסף לו). לכן הכלי מכיר כעת **שתי מערכות מספור** — שיעורים ופרקים — ומדפיס את שתי
הטבלאות. **הרצה נקייה: 885 מראי מקום, 991 בדיקות עמוד, 0 אי־התאמות.** הראיה וההכרעה —
`docs/DECISIONS.md`; מפות השיעורים והפרקים — §0.3.1 ב-`docs/SPEC_DINIM_VESATOT.md`.
מה שמתוקן אוטומטית: ציטוט החולש על עמוד אחד, בקבוצה שבה לפחות חמישה ציטוטים בעלי אותה
הסטה (ושלא תערבב ציטוטי פרק עם ציטוטי שיעור).

`ocr_scanned_hebrew_pdf.py` מטפל במקרה השני: ספרים **סרוקים כתמונות בלבד**. הוא
מחלץ את התמונה המוטבעת, מאתר את **זווית הסיבוב** (סריקות רבות מסובבות 90°, וסיבוב
שגוי מייצר ג'יבריש מוחלט ב-OCR), מחיל סף Otsu, ומריץ Tesseract עם מודל `heb`.
שימש לקריאת "דעת טהרה" — 42,340 תווי עברית מ-16 עמודים.

**מגבלת דיוק חשובה:** כלי ה-OCR משבש תווים באופן שיטתי (בעיקר ס↔פ) ומשזר טורים.
אין לצטט מלולית מפלטו, והמסמך `docs/SPEC_DINIM_VESATOT.md` מציין מגבלה זו במפורש.

פלטי שני הכלים אינם נכנסים ל-git (זכויות יוצרים) — ראו `.gitignore`.
