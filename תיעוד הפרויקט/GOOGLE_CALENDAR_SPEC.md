## 1. תקציר מנהלים ומטרת הפיצ'ר

### הצורך
משתמשי אפליקציית "לוח טהרה" זקוקים לתזכורות אמינות בזמן אמת עבור:
* בדיקות הפסק טהרה ומוך דחוק (לפני שקיעה).
* בדיקות שבעה נקיים (בבוקר ולפני שקיעה).
* עונות פרישה (עונת יום/לילה, עונה בינונית, הפלגה, החודש, וסתות קבועים ומיחושים).
* טבילה במקווה.

היות שמדובר באפליקציית שולחן עבודה (Electron Desktop App), האפליקציה אינה פועלת 24/7 והמחשב עלול להיות כבוי בזמני התזכורת. כמו כן, האפליקציה מחויבת לפעול ללא תקציב שרתים (Zero-Cost Architecture).

### הפתרון
מינוף תשתית ה-**Google OAuth 2.0** הקיימת באפליקציה (המשמשת לגיבוי Google Sheets) לטובת **סנכרון לוח שנה ייעודי ב-Google Calendar**.  
Google Calendar משמש כ-Backend חינמי מבוזר:
* שרתי גוגל מתזמנים ושולחים את **התראות המייל (Email Reminders)** ואת **התראות ה-Push** ישירות למשתמש.
* השליחה מבוצעת בדיוק בזמן, **גם כשהמחשב של המשתמש כבוי לחלוטין**.
* עלות שרתים ותפעול: **0 ש"ח**.

## 2. עקרונות מנחים: פרטיות, דיסקרטיות ואפס עלות

### א. יומן נפרד ומבודד (Secondary Calendar)
* **איסור מוחלט על כתיבה ליומן הראשי (Primary Calendar)** של המשתמש.
* האפליקציה תיצור יומן משני נפרד בשם מוגדר (למשל: `תזכורות אישיות` או שם מותאם אישית).
* **יתרונות:**
  1. המשתמש יכול להסתיר/להציג את היומן בלחיצת כפתור אחת במסך Google Calendar מבלי לפגוע ביומן העבודה/המשפחה שלו.
  2. במקרה של ניתוק או איפוס, ניתן למחוק את היומן כולו בבת אחת בלי להשאיר שאריות.

### ב. מדרג דיסקרטיות (Privacy Levels)
בשל הרגישות ההלכתית והאישית, יש לספק למשתמש בהגדרות שליטה מלאה על שמות האירועים וההתראות:
1. **מפורט (Detailed):** "בדיקת שחרית - יום 3 לשבעה נקיים", "עונת פרישה - עונה בינונית".
2. **סולידי (Subtle - ברירת מחדל):** "בדיקה - בוקר", "בדיקה - מנחה", "עונת פרישה (יום)".
3. **מוצפן / שמות קוד (Discreet):** "תזכורת א'", "תזכורת ב'", "תזכורת ערב", או קידומת מותאמת אישית שהמשתמש בוחר בעצמו (למשל: "פגישה 1").

### ג. רמת נראות האירוע (Visibility)
* כל האירועים ייווצרו כ-`visibility: "private"` — כך שאם המשתמש משתף את לוח השנה שלו עם אנשים אחרים (כגון שיתוף יומנים בארגון או במשפחה), פרטי האירוע מוסתרים לחלוטין.

## 3. ארכיטקטורת המערכת (Main vs Renderer)

המערכת תמשיך את הדפוס הארכיטקטוני הקיים של `googleBackup.js` ו-`main.js`:

```
┌─────────────────────────────────────────────────────────────┐
│                       Renderer Process                      │
│                                                             │
│  js/googleCalendar.js                                       │
│    ├─ חישוב רשימת אירועים נדרשים מול calculations.js & zmanim  │
│    ├─ בדיקת Delta מול האירועים הקיימים ביומן                │
│    ├─ יצירה / עדכון / מחיקה באמצעות fetch ישיר ל-Google API  │
│    └─ ניהול State מקומי (localStorage / db)                 │
└──────────────────────────────┬──────────────────────────────┘
                               │  window.api.oauthEnsureToken()
                               │  (מבקש לוודא טוקן תקף לפני קריאות)
                               ▼
┌─────────────────────────────────────────────────────────────┐
│                         Main Process                        │
│                                                             │
│  main.js                                                    │
│    ├─ הזרקת כותרת Authorization: Bearer <token> דרך:        │
│    │    session.defaultSession.webRequest.onBeforeSendHeaders│
│    │    לכל קריאה שמתחילה ב:                                │
│    │    https://www.googleapis.com/calendar/v3/              │
│    ├─ ניהול Refresh Token וחידוש Access Token שפג           │
│    └─ שמירת מזהה היומן שנוצר (calendarId) ב-oauth store    │
└─────────────────────────────────────────────────────────────┘
```

### שינויים נדרשים ב-`main.js`:
1. **הרחבת הסינון ב-`addAuthHeaderToRequests`:**
   הוספת ה-Endpoint של Calendar:
   ```javascript
   details.url.startsWith('https://www.googleapis.com/calendar/v3/')
   ```
2. **היקפי הרשאה (Scopes):**
   * שימוש בהיקף: `https://www.googleapis.com/auth/calendar` (נדרש ליצירת יומן נפרד, מחיקתו וניהול אירועים בו).
   * שמירת `calendarId` בקובץ `userData/google-oauth-store.json`.

## 5. מודל נתונים ומבנה אירוע ב-Google Calendar

כדי לאפשר זיהוי חד-חד-ערכי, מניעת כפילויות ומחיקה קלה, נשתמש בשדה `extendedProperties.private` של Google Calendar:

```json
{
  "summary": "בדיקה - בוקר",
  "description": "תזכורת בדיקת בוקר (יום 3 לשבעה נקיים)\nהופק ע\"י לוח טהרה",
  "start": {
    "dateTime": "2026-09-21T08:30:00+03:00",
    "timeZone": "Asia/Jerusalem"
  },
  "end": {
    "dateTime": "2026-09-21T09:00:00+03:00",
    "timeZone": "Asia/Jerusalem"
  },
  "visibility": "private",
  "transparency": "transparent", 
  "reminders": {
    "useDefault": false,
    "overrides": [
      { "method": "email", "minutes": 120 },
      { "method": "popup", "minutes": 30 }
    ]
  },
  "extendedProperties": {
    "private": {
      "app": "taharah-board",
      "syncKey": "check_day3_morning_739880",
      "eventType": "check",
      "checkPart": "morning",
      "dateAbs": "739880"
    }
  }
}
```

* `transparency: "transparent"`: מסמן את המשתמש כ-"פנוי" (Available) כדי שלא יחסום פגישות עבודה ביומן.
* `syncKey`: מפתח ייחודי הנגזר מסוג האירוע והתאריך האבסולוטי (`dateAbs`).

## 6. מנוע הסנכרון (Sync Engine): מחזור חיים, מחיקות ושינויים

זהו החלק המורכב והקריטי ביותר במערכת.

### א. תרחיש סתירת ספירה ושינוי נתונים (Halachic Resets)
אם משתמשת רואה דם ביום ה-4 לשבעה נקיים, או משנה תאריך ראייה קודם:
1. כל הבדיקות של ימים 4–7 והטבילה המתוכננת **כבר אינם תקפים**.
2. אסור להשאיר תזכורות שגויות ביומן.
3. **עקרון הדלתא (Reconcile / Diff Algorithm):**
   * המנוע שולף את כל האירועים העתידיים הקיימים ביומן האפליקציה (`timeMin = now`).
   * המנוע מחשב את רשימת האירועים העתידיים **התקפים** לפי המצב הנוכחי בתוכנה.
   * **אירועים שקיימים ביומן אך אינם ברשימה המחושבת -> נמחקים מיידית (`DELETE`).**
   * **אירועים שאינם ביומן אך קיימים ברשימה המחושבת -> נוצרים (`POST`).**
   * **אירועים שקיימים בשניהם אך זמנם השתנה -> מעודכנים (`PATCH`).**

### ב. טריגרים להפעלת סנכרון:
1. **טריגר מיידי:** בעת שמירת אירוע חדש בתוכנה (ראייה, הפסק, שינוי הגדרות). Debounced ל-3 שניות למניעת הפצצת קריאות.
2. **טריגר פתיחה:** בעת פתיחת האפליקציה (אם עברו יותר מ-12 שעות מהסנכרון האחרון).
3. **טריגר ידני:** לחיצה על כפתור "סנכרן יומן כעת" במסך ההגדרות.

## 7. מפרט קריאות ה-API (Endpoints & Payloads)

כל הקריאות מבוצעות ב-`fetch` ישיר מה-Renderer. ה-Main Process מצרף אוטומטית כותרת `Authorization: Bearer <token>`.

### 1. איתור או יצירת היומן הייעודי
* **בדיקת קיום היומן:**
  `GET https://www.googleapis.com/calendar/v3/users/me/calendarList`
  מחפשים יומן שבו `summary === "לוח טהרה - תזכורות אישיות"` (או לפי `calendarId` שנשמר ב-store).
* **יצירת יומן חדש (אם לא קיים):**
  `POST https://www.googleapis.com/calendar/v3/calendars`
  ```json
  {
    "summary": "לוח טהרה - תזכורות אישיות",
    "description": "תזכורות בדיקות וימי פרישה מאפליקציית לוח טהרה",
    "timeZone": "Asia/Jerusalem"
  }
  ```
  ה-`id` שחוזר נשמר ב-`userData/google-oauth-store.json` תחת המפתח `calendarId`.

### 2. שליפת אירועי האפליקציה הקיימים
* `GET https://www.googleapis.com/calendar/v3/calendars/{calendarId}/events?timeMin={ISO_NOW}&privateExtendedProperty=app=taharah-board`

### 3. יצירת אירוע חדש
* `POST https://www.googleapis.com/calendar/v3/calendars/{calendarId}/events`

### 4. עדכון אירוע קיים
* `PATCH https://www.googleapis.com/calendar/v3/calendars/{calendarId}/events/{eventId}`

### 5. מחיקת אירוע מבוטל
* `DELETE https://www.googleapis.com/calendar/v3/calendars/{calendarId}/events/{eventId}`

## 8. ממשק משתמש והגדרות (UI/UX)

במסך ההגדרות (`index.html`), תחת לשונית החיבורים או בסמוך לכרטיס הגיבוי הקיים, יתווסף כרטיס: **"יומן גוגל והתראות דוא\"ל"**:

### רכיבי הכרטיס:
1. **מתג ראשי (Toggle):** הפעל/השבת סנכרון ליומן גוגל.
2. **סטטוס חיבור:**
   * "מחובר ליומן: לוח טהרה - תזכורות אישיות (אימייל@gmail.com)"
   * "סנכרון אחרון: היום בשעה 10:15" + אייקון סטטוס ירוק.
3. **בחירת רמת דיסקרטיות (Select Box):**
   * *סולידי (מומלץ):* "בדיקה - בוקר", "עונת פרישה"
   * *מוצפן:* "תזכורת 1", "תזכורת 2"
   * *מפורט:* שמות מלאים של הבדיקות והעונות
4. **ערוצי התראה מבוקשים (Checkboxes):**
   * [x] שלח התראות בדוא"ל (Email)
   * [x] הצג התראות בנייד/בדפדפן (Notification / Popup)
5. **תזמוני ברירת מחדל:**
   * שעת בדיקת בוקר: תיבת בחירת שעה (ברירת מחדל 08:30).
   * זמן תזכורת לפני השקיעה: תיבת בחירה (30 דק' / 45 דק' / 60 דק' / שעתיים).
6. **כפתורי פעולה:**
   * כפתור **"סנכרן כעת"** (עם ספינר טעינה).
   * קישור **"פתח את יומן גוגל בדפדפן"** (`calendar.google.com`).
   * כפתור **"נקה את כל תזכורות האפליקציה מהיומן"** (להסרה נקייה).

## 9. היבטי Google OAuth ואימות מול גוגל (Verification)

### א. תמיכה בסביבת פיתוח (לפני אימות מלא)
* בהגדרת ה-OAuth ב-Google Cloud Console, מוסיפים את ההיקף:  
  `https://www.googleapis.com/auth/calendar`
* **בשלב הפיתוח והבדיקות:** הפרויקט נמצא בסטטוס "Testing". מזינים ב-Test Users את כתובות הגוגל של המפתח והבודקים (עד 100 משתמשים). בשלב זה הכל עובד תקין לחלוטין ללא שום אזהרות.

### ב. מעבר ל-Production ואימות (למעלה מ-100 משתמשים)
כדי לאפשר ל-2,000+ משתמשים להתחבר ללא מסך אזהרה:
1. **עמוד מדיניות פרטיות (Privacy Policy):**
   * עמוד אינטרנט פשוט ב-GitHub Pages או אתר ייעודי.
   * הצהרה מפורשת: "האפליקציה יוצרת אירועים ביומן Google של המשתמש לצורך תזכורות אישיות בלבד. המידע אינו נאסף, אינו מועבר לצד שלישי ואינו משמש למטרות פרסום".
2. **סרטון הדגמה (Demo Video ל-YouTube כ-Unlisted):**
   * הקלטת מסך של דקה וחצי.
   * הצגת לחיצה על כפתור החיבור באפליקציה.
   * **חובה:** הצגת שורת הכתובות בדפדפן כאשר ה-Client ID גלוי.
   * אישור ההרשאות.
   * הצגת היומן `calendar.google.com` עם האירועים והתראות המייל שנוצרו.

## 10. צ'קליסט משימות מפורט לקלוד קוד (Implementation Steps)
